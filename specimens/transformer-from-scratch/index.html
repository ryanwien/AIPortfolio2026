SP-02 Trained end to end

transformer-from-scratch

Containment class — structural

A decoder-only transformer implemented from first principles in PyTorch — no nn.Transformer, no high-level wrappers. The point is to show the mechanics are understood, not assembled.

Loss
3.38 → 1.93
Parameters
~0.5M (tiny config)
Tokenisation
character-level
Trains on
CPU, a few minutes

Why this exists

Wrapping a high-level API proves nothing about understanding. This is attention, masking, and the training loop written out by hand, so every design choice has to be made explicitly rather than inherited from a library default.

Every non-obvious decision is commented in model.py: why scaled dot-product attention divides by √d, why the mask is what makes it a decoder, why pre-norm rather than post-norm, and why the input embedding is tied to the output projection.

It is trained end to end and verified to converge — loss 3.38 down to 1.93 — producing coherent character-level samples. Enough to prove the loop works; deliberately not a scale demonstration.

What is measured

Convergence
Loss falls from 3.38 to 1.93 on the default tiny config, on CPU.
Multi-head causal attention
Written by hand, including the mask logic that makes it a decoder.
A correct training loop
Batching, loss, gradient clipping, AdamW, evaluation and sampling.
Documented choices
√d scaling, pre-norm placement and weight tying, explained inline rather than copied.

Layout

transformer-from-scratch/
├── src/
│   ├── model.py     # attention, MLP, blocks, GPT
│   ├── data.py      # char-level dataset + batching
│   └── train.py     # training loop, eval, sampling
└── notebooks/
    └── walkthrough.md   # annotated tour of each component

Run it

pip install -r requirements.txt
# any plain-text file works; a few hundred KB is plenty
python -m src.train --data data/corpus.txt --steps 2000

Limitations

  • Character-level tokenisation, chosen for simplicity — no BPE.
  • No KV-cache, so generation is O(n²) per step. Fine at this scale, not for serving.
  • Trained on a toy corpus to keep the repo reproducible on a laptop.

What I would do next

  • Add a BPE tokeniser and compare convergence against char-level.
  • Implement a KV-cache and benchmark the generation speedup.
  • Ablate pre-norm vs. post-norm and weight tying on/off, with loss curves.
