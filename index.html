Field note — 001

        
The fence is
the interesting part.

        

          I work on the unglamorous half of the field: knowing when a model is
          actually working. A system that looks brilliant in a screen recording
          tells you almost nothing. What it does on held-out cases, at the tail
          of the latency distribution, on the day it fails — that is the
          measurable part, so that is the part I build first.
        

        

          Every enclosure here ships with an evaluation story, a documented set of
          limitations, and honest notes on what I would do next. A few rigorous
          repos beat many shallow ones.

    Containment class — structural

  4. 
          
    
          
    
            SP-04
            Runner scoring
          
    
          
    extraction-benchmark
    
          
    Containment class — methodology
    
          
    A small, rigorous structured-extraction benchmark. Benchmarks get cited, so the credibility comes from a defensible method rather than a flattering score.
    
          
    
            
    Measured
    Regex baseline at 0.80 field F1 — a floor every model must beat
    
            
    Headline metric
    Field-level F1, with strict exact-match reported beside it
    
            
    Normalization
    Explicit and documented — silent normalization is how benchmarks mislead
    
          
    
          
    Limitation Three illustrative examples shipped; a credible benchmark needs 50+ hand-labelled cases and a second annotator.
    
          
    • Python
    • Multi-model scoring
    • Field-level F1

  5. 
          
    
          
    
            SP-05
            Verified on synthetic
          
    
          
    stock-forecasting
    
          
    Containment class — volatile
    
          
    Next-day return forecasting done correctly, where the easy mistakes quietly produce results that look great and mean nothing. The discipline is the deliverable.
    
          
    
            
    No lookahead
    Every feature at t uses only data available at or before t
    
            
    Split
    Strictly chronological; scaling fit on train only
    
            
    Judged by
    Directional accuracy and a long/flat backtest against buy-and-hold
    
          
    
          
    Limitation Expect directional accuracy near 0.5. A portfolio claiming 70% almost always has a leak — that honesty is the point.
    
          
    • PyTorch LSTM
    • yfinance
    • Sharpe & drawdown
    
          
    
            Open dossier → — stock-forecasting
            Code — stock-forecasting on GitHub

Station protocols

        
The rules every enclosure is built to. Posted where you can read them.

      

      
    
        
  1. 01Reproducible. Pinned dependencies, deterministic seeds, one command to run it.
    2. 
        
  2. 02Results are versioned artifacts. Never a screenshot.
    3. 
        
  3. 03Every README ends with limitations. Followed by what I would do next.
    4. 
        
  4. 04No secrets in any repo. API keys are read from the environment at runtime.
    5. 
        
  5. 05Measurement over demos. If it cannot be measured, it does not ship.
